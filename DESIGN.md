# «Хаос Дня»: задачи и дневник

Редакция 3, 6 ноября 2026 года. Владелец согласовал единое место для планирования: раздел «Дела». Дневник показывает прожитый день и точку продолжения. Методика описана в [версии 0.7](docs/methodology/2026-11-05-self-organization-under-uncertainty.md).

## Назначение разделов

- «Дела»: место хаоса, проекты, задачи, день работы, срок результата, ожидание и пересмотр.

Место хаоса заменяет входящие как единственную быструю корзину. Запись там ещё не задача и не заметка: сфера, проект и срок не назначаются. «Не может ждать» поднимает строку и показывает её в «Сегодня». «Это задача» и «Это заметка» уводят запись из корзины. Дневник от этого не пополняется. ИИ эту корзину пока не разбирает.
- «Дневник»: что произошло, что сделано и на чём остановилась работа.
- «Заметки»: справочные материалы, идеи и черновики без привязки к дню.
- «Спросить»: необязательный чат с QwenCloud по заметкам.

Боковая панель «План на день» убрана из дневника. Раньше она показывала часть тех же задач по выбранной дате, но выглядела как второй независимый список. Существующие задачи, даты и связи сохраняются в общей модели.

## Переходы и создание задачи

«Новая задача» в меню «Файл», сочетание ⇧⌘N и команда в строке меню открывают существующий редактор в «Делах». Команда работает и при переходе из дневника. Уже открытый редактор задачи или проекта повторным вызовом не заменяется.

Команды показа и скрытия плана, кнопка боковой панели и отдельный редактор пункта плана удалены. «Новая запись» по ⌘N по-прежнему открывает ввод в дневнике.

## Макет дневника

```
┌ Дела | Дневник | Заметки | Спросить                         ┐
│ ‹ ›  Сегодня  [дата]                         Итог дня     │
│ Дата крупно                    Поиск по всем дням         │
│ Относительный день и день недели                          │
│ Что сделано или произошло?                               │
│ Другое время   На чём остановился   Записать               │
│                                                         │
│ 09:30 ●  Событие                                         │
│       │                                                 │
│ 14:05 ✓  Выполненная задача                              │
│       │  Точка продолжения                              │
└─────────────────────────────────────────────────────────┘
```

Лента занимает доступную ширину. Заголовок даты, ввод и поиск остаются на прежних местах. Время выровнено по правому краю своей колонки; на оси отображается точка, а у выполненной задачи галочка.

## Связь задачи и записи

Выполнение задачи в «Делах» атомарно создаёт одну запись дневника с текущим временем. Повторная отметка не создаёт вторую запись. Возврат задачи в работу удаляет связанную запись только если её не меняли; изменённая запись остаётся. Удаление задачи сохраняет запись, удаление записи сохраняет отметку выполнения задачи.

Шаги хранятся в необязательном массиве `DayPlan.steps`: устойчивый ID, текст, время выполнения. Порядок массива задаёт линейный порядок, родитель задаётся вложенностью. Это части одной задачи, без собственных сроков, проектов и записей дневника. Формат v5 читает прежние v1-v4 и создаёт копию перед первым сохранением шагов. JSON и Markdown сохраняют связь, порядок и выполнение.

Команда «Разбить на шаги» открывается из задачи в «Делах». Редактор разделяет сохранённые шаги и ещё не утверждённое предложение. Новые шаги, в том числе ручные, утверждаются через «Добавить шаги». Изменение, удаление, перестановка и отметки сохранённых шагов применяются через отдельную кнопку сохранения. Следующий незавершённый шаг виден в строке исходной задачи.

Перед запросом показаны название, подробности и необязательные уточнения. Ответы на 1-3 вопроса также видны перед следующей отправкой. Другие задачи, дневник, заметки, сохранённые шаги и предыдущие предложения автоматически не включаются. Регенерация явно подтверждается и меняет только черновик предложения. Ошибка, отмена и поздний ответ не заменяют текущий черновик. Он хранится в AppState до выхода из приложения. При конфликте можно перечитать данные без потери предложения и ответов.

Контекст происхождения предложения и ответов хранится отдельно от свежего снимка родителя. Смена названия или подробностей блокирует добавление и запросы до явного пересмотра либо удаления прежнего черновика. В окне видны оба контекста, старое предложение и уточнения не удаляются автоматически. Перезагрузка списка шагов не снимает блокировку, а изменение только порядка сохранённых шагов не меняет контекст. Обновление уже созданного черновика выполняется в refresh AppState; получение объекта при построении sheet не публикует изменений. Поля и команды строк находят актуальный шаг по ID при каждом обращении, включая отложенные callback после удаления.

Окно шагов имеет высоту 640 с прокруткой содержимого и постоянной кнопкой закрытия. Высота редактора исходной задачи остаётся 650. Локальная версия 0.2.4 build 6 не означает публикацию выпуска.

Результат родителя подтверждается отдельно, независимо от отметок шагов. Выполнение родителя сохраняет шаги, правки доступны после возврата задачи в работу. Удаление родителя с любыми шагами отклоняется: сначала нужно явно удалить шаги и сохранить список. Каскадного удаления нет. [План и решения](docs/plans/2026-11-06-task-breakdown.md).

## Проверка изменения

Существующие self-tests ядра проверяют хранение, совместимость и связь выполнения с дневником. UI проверяется сборкой и отдельным временным профилем: нет панели плана и её команды, ⇧⌘N открывает «Дела», выполнение появляется в дневнике, повторный вызов не затирает открытый редактор. Перед заменой установленного приложения сохраняется резервная копия.
