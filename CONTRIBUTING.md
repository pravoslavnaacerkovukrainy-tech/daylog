# Как предложить изменение

«Хаос Дня» - личный проект с одним владельцем. Сообщения об ошибках и идеи принимаются через [Issues](https://github.com/pravoslavnaacerkovukrainy-tech/daylog/issues). Прежде чем писать код для pull request, откройте issue и дождитесь ответа: так работа не разойдётся с планами проекта.

## Не прикладывайте личные данные

Не прикладывайте к issue и pull request:

- файл `~/Library/Application Support/Daylog/entries.json` и его резервные копии `entries-before-….json`;
- экспорт в папку Markdown, тексты записей дневника, заметок и задач;
- снимки экрана с личными записями.

Чтобы показать ошибку, воспроизведите её на отдельных данных:

```bash
DAYLOG_DATA_DIR="$(mktemp -d)" "/Applications/Хаос Дня.app/Contents/MacOS/Daylog"
```

Приложение создаст пустой профиль во временной папке. Заполните его вымышленными строками и приложите их или снимок окна.

## Что подходит проекту

Перед предложением функции прочитайте [подход к дизайну](DESIGN.md) и [методику](docs/methodology/2026-11-05-self-organization-under-uncertainty.md). Коротко:

- приложение помогает выбрать следующее действие, когда планы меняются;
- в нём нет таймеров, серий, очков, оценок продуктивности и напоминаний;
- «Кому обещано» остаётся свободной строкой, адресной книги нет;
- шаги можно ввести вручную, запрос к Groq требует явного действия, в тестах используется подмена ответов и вымышленные данные;
- проект не обещает медицинского или психологического эффекта;
- основные данные хранятся на Mac, телеметрии и фоновых подключений нет.

Предложения, которые противоречат этим правилам, скорее всего будут закрыты.

## Если код всё же нужен

1. Сборка и тесты описаны в разделе [«Разработка»](README.md#разработка). Нужен Swift из Command Line Tools, полный Xcode не требуется.
2. Держите репозиторий вне `~/Documents`: FileProvider может повредить сборку и подпись.
3. Перед pull request выполните:

   ```bash
   bash test.sh                          # проверки ядра без сети и без ваших данных
   DAYLOG_ADHOC_SIGN=1 bash build.sh     # сборка без обращения к Keychain
   ```

4. Если меняется формат `entries.json`, опишите в pull request, как читается прежний файл и какая резервная копия создаётся перед первым сохранением.
5. Текст интерфейса пишется по-русски, с обычным дефисом вместо длинного тире.
6. Один pull request - одна задача. Опишите, что проверено вручную, а что нет.
