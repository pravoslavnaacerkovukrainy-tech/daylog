# Заметочник в «Ход дня» — дизайн

Дата: 2026-11-01
Статус: согласован, ожидает вычитки перед планом реализации

## Цель и контекст

«Ход дня» (Daylog) — нативное macOS-приложение (SwiftUI, swiftc без Xcode),
личный дневник + простой план дня, всё локально в одном
`~/Library/Application Support/Daylog/entries.json`.

Сверхзадача приложения — помощь при СДВГ: пользователь часто начинает полезное,
переключается, и прежнее повисает недоделанным. Конкретный механизм «возврата к
брошенным хвостам» сознательно НЕ проектируется сейчас — это отдельный будущий этап.

Этот спек описывает **один** этап: добавить третье пространство — **заметочник**.
Смысл заметок: пользователь сумбурно вываливает мысли, чтобы разгрузить голову,
а ИИ (xAI/Grok, уже интегрирован) делает из наброска заголовок и полноценную
оформленную заметку.

Три пространства приложения после этого этапа:
1. **Записи дневника** — датированный лог «делаю / сделал». Уже есть. Не меняется.
2. **План дня (задачи)** — «собираюсь сделать сегодня», галочка → запись. Уже есть. Не меняется.
3. **Заметки** — вне времени: идеи, справка, недоделанные хвосты. **Строим.**

## Решения (зафиксированы с пользователем)

- У заметки есть заголовок.
- Сырой набросок **не хранится**: поле ввода замещается оформленным текстом.
- ИИ запускается **по кнопке** «Оформить», не автоматически.
- Порядок списка: **новые сверху + закреплённые сверху всех** (pin).
- Заметки строим первыми (до любого СДВГ-механизма).
- Явно вне объёма (YAGNI): теги, связи заметка↔задача/запись, вложения,
  напоминания, второй ключ API, авто-запуск ИИ.

## 1. Модель данных (`Sources/Core/DiaryCore.swift`)

Новая структура, по образцу `DiaryEntry`/`DayPlan`:

```swift
public struct DiaryNote: Codable, Identifiable, Equatable, Hashable {
    public var id: UUID
    public var title: String
    public var body: String
    public var createdAt: Date
    public var updatedAt: Date
    public var pinned: Bool
}
```

- `body` — обязательный (непустой после trim), иначе `DiaryError.emptyText`.
- `title` — необязательный: может быть пустым, в списке пустой показывается как
  «Без заголовка». В ИИ-пути заголовок всегда есть; пустой нужен только для быстрого
  ручного ввода без ИИ.
- `pinned` по умолчанию `false`.
- Даты нормализуются `diaryNormalized` (до секунды), как у остальных.

### Документ версии 3

`DiaryDocument` получает `notes: [DiaryNote]`:
- `currentVersion = 3`.
- Вычисление версии: v3 если `!notes.isEmpty`; иначе прежняя логика (v2 при планах/связях, иначе v1).
- `encode`: ключ `notes` пишется только если непусто (как `plans`).
- `init(from:)`: `notes` декодируется как опциональный, по умолчанию `[]`.
- Заголовочная проверка версий в `DiaryJSON.decode`: верхняя граница — `currentVersion` (3).

### Обратная совместимость

- Файл **без заметок** остаётся v1/v2 — прежняя сборка читает без изменений.
- Файл **с заметками** — v3; прежняя сборка (понимает ≤2) выдаёт
  `unsupportedFormat("версия 3…")` — аккуратный отказ, не «битый файл».
- Новый файл с заметками, открытый новой сборкой, читается полностью.
- Round-trip: v3 → encode → decode даёт те же `entries/plans/notes`.

## 2. Хранилище (`DiaryStore`)

- Поле `public private(set) var notes: [DiaryNote] = []`.
- `load()` заполняет `notes` (отсортированные), `persist(...)` пишет
  `entries + plans + notes` одним атомарным файлом. Единая точка записи сохраняется:
  любое изменение сперва на диск, потом в память; при `blockReason` — исключение.
- `persist` расширяется третьим параметром `notes`.
- Методы (все через `persist`, с тем же стилем ошибок `DiaryError`):
  - `addNote(title:body:now:) -> DiaryNote`
  - `updateNote(id:title:body:now:) -> DiaryNote` (обновляет `updatedAt`)
  - `setPinned(id:_ pinned:Bool,now:) -> DiaryNote` (обновляет `updatedAt`? — нет:
    закрепление не считается правкой содержимого, `updatedAt` НЕ трогаем, чтобы pin не
    перетасовывал список по дате; порядок задаётся отдельно, см. `sortedNotes`).
  - `deleteNote(id:) -> DiaryNote`
  - `restoreNote(_:)` — возврат удалённой (undo), как `restore` для записей.
  - `searchNotes(_:) -> [DiaryNote]` — регистронезависимо и без диакритики (как `search`),
    по `title` и `body`; сначала закреплённые, затем по `updatedAt` вниз.
  - `sortedNotes() -> [DiaryNote]`: закреплённые (по `updatedAt` вниз) → остальные (по `updatedAt` вниз).
    Детерминированный доразрыв по `id.uuidString`.
- `cleanText`/валидация: `body` непустой → иначе `DiaryError.emptyText`. `title` триммится, пустой допустим.

## 3. ИИ-операция (`Sources/Core/NotePolish.swift`)

Отдельный файл рядом с `DraftPolish.swift`, тот же эндпоинт/модель/`store:false`,
тот же ключ из `XAIKeyStore` (второго ключа нет).

- `model = "grok-4.7"`, `endpoint = https://api.x.ai/v1/responses`.
- `maxCharacters = 6000` (наброски длиннее записей).
- Системный промпт (суть): «Из сырого наброска сделай чистую заметку. Верни СТРОГО
  JSON-объект `{"title": "...", "body": "..."}` и ничего кроме него. title — короткий
  (до ~60 знаков). body — связный, по возможности структурированный текст заметки.
  Сохрани все факты, имена и числа. Ничего не выдумывай и не оценивай. Язык — как у наброска.»
- `requestBody(draft:)` — как у `DraftPolish` (system + user), с проверками пустоты и лимита.
- `parse(_:) -> (title: String, body: String)`:
  1. Достать текст из ответа Responses API (см. рефактор ниже).
  2. Снять ``` -ограду, если есть (повторно использовать логику очистки).
  3. Распарсить как JSON `{title, body}`.
  4. **Фолбэк** при неудаче JSON: `body` = весь очищенный текст; `title` = первая
     непустая строка (обрезанная до ~60 знаков), либо «Без заголовка».
- `NotePolishClient.polish(draft:apiKey:) async throws -> (title, body)` — как `DraftPolishClient`,
  включая маппинг `URLError.cancelled` → `CancellationError`, проверку HTTP-кода и
  `DraftPolishError` (переиспользуем существующий тип ошибок — он общий для xAI).

### Рефактор (targeted, по месту)

Разбор ответа Responses API (обход `output` → пропуск `reasoning` → сбор `content`/
`output_text`) сейчас живёт только в `DraftPolish.parse`. Вынести общий помощник:

```swift
public enum XAIResponses {
    public static func extractText(_ data: Data) throws -> String
}
```

`DraftPolish.parse` и `NotePolish.parse` используют его. `DraftPolish` поверх применяет
свой `cleanOutput` (одна фраза), `NotePolish` — свой JSON-разбор. Только извлечение
текста общее; поведение обоих не меняется (покрыто тестами).

## 4. UI (`Sources/App/`)

### Режимы окна

Переключатель в тулбаре: сегмент **«День» / «Заметки»**. Состояние — в `AppState`
(`@Published var mode: AppMode` = `.day | .notes`, по умолчанию `.day`).
Режим «День» — нынешний экран без изменений. Режим «Заметки» — новый экран.

### Экран «Заметки»

Две колонки:
- **Список** (слева): закреплённые сверху, затем новые; строка = заголовок + первая
  строка текста + дата; иконка закрепления; поле поиска сверху; кнопка «Новая заметка».
- **Редактор** (справа): поле заголовка (однострочное) + поле текста (многострочное).
  - Кнопка **«Оформить»**: зовёт `NotePolishClient` с текущим текстом редактора,
    на время — индикатор занятости; по ответу заполняет заголовок и замещает текст в полях.
    Ошибки — через существующий механизм статуса/ошибки (`showError`/`showDraftStatus`)
    и/или sheet для отсутствующего ключа (как `keySheetIntent`).
  - **«Отменить оформление»**: возвращает заголовок/текст к состоянию до последнего «Оформить»
    (хранится только в памяти редактора, в документ сырой текст не пишется).
  - **«Сохранить»**: `addNote`/`updateNote`. Требует непустой `body`.
  - Закрепить/открепить, удалить (с undo в статус-строке — переиспользуем `UndoAction`,
    добавив `case restoreNote(DiaryNote)` и ветку в `performUndo`).

### Команды и меню

- `CommandGroup(.newItem)`: добавить «Новая заметка» (ярлык — предложу `⌘⌥N`, свободен).
  Переключает режим в `.notes`, фокус в редактор.
- `MenuBarExtra`: пункт «Новая заметка…».
- Меню «День» переименование не требуется; «Оформить» для заметок — отдельная кнопка в
  редакторе (не путать с «Причесать черновик» для записей).

### AppState

- `mode`, зеркала `notes`/`sortedNotes`/`noteSearchResults`, методы-обёртки над `store`
  (`addNote/updateNote/deleteNote/setPinned/restoreNote`), поток «Оформить»
  (токен занятости, задача, отмена) по образцу существующего polish-потока.
- `refresh()` дополнительно читает `store.notes`.

## 5. Экспорт

- **JSON**: автоматически через документ v3 (`exportJSON` уже сериализует весь документ —
  добавление `notes` в `DiaryDocument` покрывает это).
- **Markdown** (`exportMarkdown`): после дней — отдельная секция:
  ```
  ## Заметки

  ### <Заголовок> (📌 если закреплена)
  <тело>
  ```
  Порядок — как `sortedNotes`. Если заметок нет — секция не выводится.
- Шапка экспорта: добавить «Заметок: N.» если есть.

## 6. Ошибки

- `NotePolish`: нет ключа → подсказка про меню/ключ (как `DraftPolishError.noKey`);
  HTTP/битый ответ/слишком длинно → сообщение в статус-строке. Заметку всегда можно
  сохранить вручную без сети. ИИ — усилитель, не обязательное звено.
- Хранилище: при нечитаемом файле `notes` тоже блокируются (единая блокировка записи).
