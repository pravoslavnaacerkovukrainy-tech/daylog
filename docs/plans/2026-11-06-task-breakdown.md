Если одновременно изменён сохранённый список шагов, пересмотр не перезаписывает его автоматически. Ручное добавление обозначено как создание черновика.

## План

1. Добавить в DayPlan необязательный массив TaskStep: ID, текст, completedAt. Порядок массива задаёт порядок действий, вложенность в задачу задаёт связь. Это части результата задачи, без собственных сроков и записей дневника. Отдельные DayPlan и проекты не создаются.
2. Формат v5 с чтением v1-v4 и резервной копией перед переходом. Атомарное сохранение всего списка через существующий persist, проверка ожидаемой версии родителя. Экспорт JSON и Markdown сохраняет связь, порядок и выполнение.
3. Строгий Qwen-контракт: либо 3-7 шагов, либо 1-3 вопроса. Только название, подробности и явные уточнения. Ограничить весь сериализованный контекст. Никаких запросов при открытии и автоматических повторов.
4. В «Делах» открыть редактор шагов. Показать отправляемые поля. Необязательное уточнение результата, ограничений и ресурсов одним полем. Ручной список работает без ключа. Предложения и ответы живут в черновике AppState до явного удаления или закрытия приложения, ошибки и отмена его сохраняют.
5. Разделить сохранённые шаги и предложение. Новая генерация заменяет только предложение после явного запроса, сохранённые шаги не отправляются и не заменяются. «Добавить шаги» атомарно добавляет список с устойчивыми ID; повторное добавление тех же ID ничего не дублирует. Редактирование сохранённых шагов имеет отдельную кнопку сохранения.
6. Проверить fixtures, URLProtocol mock, миграцию, конфликты, экспорт, выполнение и удаление, затем test.sh и build.sh. Реальные запросы, ключи и данные не использовать.

## Поведение родителя

Все шаги можно отметить, но родитель остаётся открытым до явного подтверждения результата. При его выполнении сохраняется прежняя одна запись дневника; шаги и их отметки сохраняются. Выполненный родитель и шаги доступны для просмотра, правки только после возврата задачи в работу. Удаление родителя с любыми шагами отклоняется: сначала пользователь явно удаляет шаги в редакторе и сохраняет. Это исключает каскадное удаление. Удаление шага не меняет родителя и дневник.

## Границы

Без восстановления после перерыва, дерева подзадач, автономных действий, новых дат и синхронизации. Тексты пользователя и модельные ответы являются данными, встроенные команды не изменяют системные правила. Модельные предложения требуют проверки пользователем; отсутствие выдуманных фактов нельзя гарантировать одним промптом.

## Проверка реализации

- Fixtures и URLProtocol mock проверяют точный состав разрешённых полей, модель и endpoint, ограничения, вопросы, явные ответы, пустой/неверный/слишком большой/обрезанный ответ, отмену, HTTP 401/429/500 и отсутствие автоматических повторов.
- Тесты реального TaskBreakdownDraft с внедрённым провайдером проверяют сохранение предложения и ручных правок, вопросы и ответы, перегенерацию, отмену и поздний ответ, перезагрузку после конфликта. Keychain не вызывается.
- Хранилище проверяется на порядок, связь через родителя, ручные правки, отметки, повторное добавление по ID, подтверждение родителя, безопасное удаление, v4-v5 backup, JSON round-trip, оба вида Markdown экспорта, конфликт снимка и файла, занятую блокировку.
- Для sandbox скрипты используют build/ModuleCache. Проверочная сборка: DAYLOG_ADHOC_SIGN=1 bash build.sh, без поиска удостоверения в Keychain.

## Оставшаяся ручная проверка

Автоматические тесты проверяют модель и состояние редактора, сборка проверяет SwiftUI. Геометрия окна, клавиатурная навигация, VoiceOver и нажатия реальных кнопок в macOS пока не проверены. Проверять только с DAYLOG_DATA_DIR во временной папке, без вызова реального Qwen.

1. Создать искусственную задачу со сроком и подробностями. Открыть команду из строки и из редактора задачи.
2. Ввести вручную три шага, изменить и переставить их, добавить, затем отметить один и сохранить. Проверить следующий шаг после перезапуска.
3. Закрыть окно с черновиком и открыть снова. Проверить явный сброс только списка сохранённых шагов при перезагрузке.
4. Подтвердить результат родителя с незавершённым шагом. Убедиться, что шаги остались, а в дневнике появилась одна запись. Вернуть задачу в работу.
5. Проверить отказ удаления родителя с шагами, затем явно удалить шаги, сохранить и удалить родителя.

Черновики не сохраняются на диск и теряются при выходе из приложения. Утверждённые шаги сохраняются на диск. Гарантировать достоверность предложений модели программно нельзя, поэтому в UI требуется проверка фактов пользователем. Реальный сетевой запрос в этой работе не выполняется.

Финальный просмотр добавил регрессионный тест AppState: повторное построение sheet со старым item получает свежего родителя, а несохранённые правки при конфликте остаются в черновике. Завершённый родитель показывает оставшееся действие как незавершённый шаг, без призыва продолжить уже подтверждённый результат.

## Исправления после независимой проверки

План: сохранить контекст происхождения черновика отдельно от свежего снимка родителя. При изменении отправляемых названия/подробностей блокировать добавление и новые запросы со старыми ответами. Показать прежние и текущие данные, дать явно подтвердить пересмотр либо удалить черновик и начать новый. Обновление сохранённых шагов без изменения контекста не требует сброса предложения.

Обновлять существующие ObservableObject при refresh AppState, а не при вычислении sheet. Поля и команды шагов привязать к ID с безопасным поведением после удаления. Высоту окна уменьшить до 640, редактора задачи до 650. Поднять только локальную версию до 0.2.4 build 6, публичную кнопку выпуска не менять. Повторить tests, ad hoc build и diff --check. Коммит не повторять.

Реализовано: sourceContext хранит прежние title/details, observedParent отслеживает текущую задачу отдельно от снимка с несохранёнными правками шагов. Проверка isContextStale защищает сам appendProposal и generate, а не только disabled у кнопок. При смене контекста отменяется текущий запрос; поздний ответ не обновляет предложение. Явный пересмотр позволяет сохранить сверенные данные, явное удаление очищает предложение, вопросы, ответы и уточнения. Отправляемые текущие поля и старый контекст показаны отдельно. Reload сохранённых шагов не подтверждает пересмотр автоматически.

Обновление AppState.refresh переносит свежий список в черновик после записи. Повторный вызов breakdownDraft(for:) из render возвращает тот же объект без objectWillChange. Регрессия воспроизводит два вручную отредактированных шага, проверяет их совпадение с JSON и массивом savedSection, затем несколько render со старым sheet item без мутаций.

Binding текста и команды строк используют ID и поиск актуальной позиции при каждом обращении. Регрессии проверяют сохранённые шаги и предложение: перестановка, удаление первой/последней строки, обращение старого Binding, поздняя команда удалённой строки и замена вопросов. Недействительный ID не меняет соседние строки и не восстанавливает удалённую.
